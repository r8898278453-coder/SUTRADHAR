2. WORKER IDENTITY, SSH PROVISIONING & PRE-FLIGHT VERIFICATION
--------------------------------------------------------------------------------

A. Deterministic Identity Generation:
- Every node calculates a unique ID upon first boot using its MAC address:
  Node ID: NODE-<SHA256(MAC)[:8]>
  Git Author: Sutradhar-<Node_ID> <<node_id>@cluster.internal>

B. Non-Interactive SSH Configuration:
- Workers authenticate exclusively via passwordless Ed25519 deploy keys.
- Interactive terminal prompts are strictly disabled:
  export GIT_SSH_COMMAND="ssh -i /opt/sutradhar/secrets/id_ed25519_worker \
    -o StrictHostKeyChecking=accept-new \
    -o BatchMode=yes \
    -o ConnectTimeout=10"
  * BatchMode=yes: Drops instantly on auth failure (Exit 255); no password prompt.
  * ConnectTimeout=10: Kills stalled handshakes after 10s.

C. 5-Point Pre-Flight Health Matrix:
1. DNS/Network: Ping api.telegram.org (HTTP 200 / RTT < 500ms).
2. Git SSH Auth: Check remote HEAD sha via git ls-remote.
3. Docker Service: Verify docker info returns Exit 0.
4. Storage/RAM: Verify >500MB free memory; prune dangling containers.
5. LLM API Key: Verify API endpoint connectivity; cascade if rate-limited[cite: 1].

3. CONSENSUS, MONOTONIC EPOCH & HYBRID MASTER EXECUTION
--------------------------------------------------------------------------------

A. Bootstrap & Dynamic Hierarchy:
- Daily bootstrap (08:00 AM) broadcasts: HELO: {node_id, uptime_seconds, epoch_id}.
- Dynamic sorting: Sort by (uptime_seconds DESC, node_id ASC).
  * Rank #1: Active Master Coordinator.
  * Rank #2 & #3: Standby Masters (Mirror state; monitor master liveness).

B. Split-Brain Lock (Monotonic Epoch Counter):
- Every leadership election increments the immutable Epoch_ID (e.g., 14 -> 15).
- If Master misses 3 heartbeats (>90s), Standby #1 claims leadership:
  PROMOTED_MASTER: {node_id: Node_Beta, epoch_id: 15}
- Reconnecting nodes compare local epoch with Telegram state. If local < cluster,
  the node instantly self-demotes to Standby mode.

C. Dual-Process Hybrid Master Engine:
- Process 1 (Orchestrator Daemon): Async thread running heartbeats, lease
  issuance, and Telegram card updates. Never blocks.
- Process 2 (Local Worker Core): Self-executes tasks if external workers == 0
  or when P0 Hotfixes (/urgent TKT-999) are triggered. Master self-signs an
  Ed25519 token (worker_id = "MASTER_LOCAL") to maintain Git security rules.

4. DAG TASK SCHEDULING & DOMAIN BOUNDARY ISOLATION
--------------------------------------------------------------------------------

A. DAG Task Graph:
- Child tasks remain in BLOCKED_ON_PARENT state until all parent tasks are
  tested and merged into tested/[cite: 1].

B. Blast-Radius Boundary (allowed_files Whitelist):
- Every ticket defines a strict mutable file list:
  {
    "ticket_id": "TKT-104",
    "assigned_to": "NODE-B7A9",
    "allowed_files": [
      "modules/matrimony/ProfileController.php",
      "tests/Unit/ProfileTest.php"
    ],
    "read_only_contracts": ["contracts/AuthInterface.php"]
  }
- Diffs touching unapproved files are rejected before running Docker compute.

C. Module Ownership & Bot-to-Bot RFC Protocol:
- If Node B (Matrimony) requires changes in Node A's module (Auth):
  1. Node B emits RFC_DELEGATION_REQUIRED event.
  2. Master pauses Node B's lease and creates sub-task TKT-104-SUB1 for Node A.
  3. Master alerts Telegram: "@Node_A: Update AuthInterface for Node_B."
  4. Node B resumes once Node A's sub-task is merged.

D. AST Breaking-Change Static Analysis:
- Sandboxed linters block breaking signature changes (altered public methods,
  missing params) to ensure backward compatibility across branches.

5. ASYMMETRIC CRYPTOGRAPHY & GIT PRE-RECEIVE GATEKEEPER
--------------------------------------------------------------------------------

A. Ed25519 Key-Pair Authentication:
- Master Node: Holds secrets/master_private_key.pem (signs leases).
- Git Server & Workers: Hold only secrets/master_public_key.pub (verifies leases).

B. Cryptographic Token Payload:
- Payload = ticket_id | worker_id | epoch_id | expiry_timestamp | files_hash
- Token Header = SEC-<Base64(Payload)>.<Base64(Ed25519_Signature)>

C. Server-Side Git Hook (hooks/pre-receive Logic):
1. Intercepts push requests on ai/TKT-* branches[cite: 1].
2. Extracts Security-Token header from the commit message.
3. Verifies Ed25519 signature against master_public_key.pub.
4. Confirms current_time < expiry_timestamp.
5. Verifies pushed branch matches ticket_id inside token.
6. Rejects with Exit 1 ("403_STALE_OR_FORGED_LEASE") if any check fails.

7. EPHEMERAL SANDBOXING & CLOSED-LOOP SELF-HEALING
--------------------------------------------------------------------------------

A. Disposable Git Worktrees:
- git worktree add /opt/sutradhar/workspaces/TKT-104 -b ai/TKT-104 origin/main[cite: 1]
- Worktree is completely purged (--force) upon completion or failure.

B. 3-Tier Patch Normalizer:
- Tier 1: git apply --check patch.diff
- Tier 2: git apply --ignore-whitespace --ignore-space-change patch.diff
- Tier 3: git apply --3way patch.diff

C. Hard-Capped Docker Sandbox:
- docker run --rm --memory="512m" --cpus="1.0" --pids-limit=100 --network="none" \
    --stop-timeout=5 -v /workspace:/workspace sutradhar-runner \
    sh -c "timeout 45s pytest /workspace/tests/"

D. Self-Healing Feedback Loop (Max 3 Retries):
- Fail (Exit != 0): Capture stderr -> Re-prompt LLM with exact stacktrace.
- Pass (Exit == 0): Sign commit with token -> Push to ai/TKT-XXX[cite: 1].
- Exhausted (3 Retries): Flag ticket NEEDS_HUMAN_REVIEW -> Push to failed/TKT-XXX.
